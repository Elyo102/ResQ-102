# שכבת היסוד — הוראות פריסה

עודכן: 22.8.2026

מה שיש כאן: ניהול תפקידים דרך Custom Claims, וכללי אבטחה שנשענים
עליהם. זה שלב 1 בסדר הבנייה.

**שום דבר מזה עדיין לא פרוס.** הקבצים מוכנים, הפריסה ממתינה למעבר
ל-Blaze.

---

## למה זה נבנה ככה

התפקיד של המשתמש נשמר בתוך טוקן ההזדהות שלו, לא כשדה במסמך.

**הרווח:** כללי האבטחה קוראים את התפקיד ישירות מהטוקן. אפס קריאות
מסמך לכל בדיקת הרשאה. בגרסה הקודמת כל פעולה עלתה 4-5 קריאות שגוגל
מחייבת עליהן — עם 39 משתמשים זה זניח, עם 3000 זה לא.

**המחיר:** רק קוד שרת יכול לכתוב לטוקן. לכן צריך Cloud Functions,
ולכן צריך Blaze.

---

## סדר הפעולות

### שלב 1 — מעבר ל-Blaze

בלי זה אי אפשר לפרוס Cloud Functions בכלל.

1. היכנס ל-https://console.firebase.google.com → פרויקט **Station-102**
2. בפינה השמאלית התחתונה כתוב **Spark** — לחץ על **Upgrade**
3. בחר **Blaze — Pay as you go**
4. חבר אמצעי תשלום
5. **חשוב:** בזמן השדרוג מוצג שדה תקציב חודשי. הגדר אותו.
   הצעה: 20 ש"ח. עם 39 משתמשים הצריכה בפועל צפויה להיות 0.

### שלב 2 — התראות תקציב

השדה בשלב 1 שולח התראה, אבל לא עוצר. שווה גם התראה נפרדת:

1. https://console.cloud.google.com/billing → Budgets & alerts
2. Create budget → בחר את הפרויקט station-102
3. סכום: 20 ש"ח לחודש
4. סמן התראה ב-50% / 90% / 100%

**למה זה חשוב:** ב-Spark חריגה ממכסה **מכבה את המוצר עד סוף החודש**.
ב-Blaze חריגה עולה כמה שקלים ואתה מקבל מייל. זו הסיבה שעוברים.

### שלב 3 — התקנת התלויות

בתיקייה `station-102-Fire`:

```
cd functions
npm install
cd ..
```

### שלב 4 — פריסה

```
firebase deploy --only firestore:rules,functions --project station-102
```

בפריסה הראשונה גוגל תבקש להפעיל כמה שירותים. אשר.

### שלב 5 — הגדרת מנהל-על (פעם אחת)

1. היכנס לאתר עם `fire102.shits@gmail.com` ואמת את המייל
2. הפעל בקונסולת הדפדפן (F12):

```javascript
const { getFunctions, httpsCallable } =
  await import('https://www.gstatic.com/firebasejs/10.12.2/firebase-functions.js');
const fns = getFunctions(undefined, 'europe-west1');
await httpsCallable(fns, 'bootstrapSuperAdmin')();
```

3. התנתק והתחבר מחדש
4. בדוק שזה עבד: `await httpsCallable(fns, 'whoAmI')()`

## הפונקציות שנכתבו

| פונקציה | מי מורשה | מה עושה |
|---|---|---|
| `bootstrapSuperAdmin` | המייל הקשיח בלבד | אתחול חד-פעמי של מנהל-על |
| `setUserRole` | מנהל-על | מעניק תפקיד, משמרת וקוד אישי |
| `approveRegistration` | מנהל-על | מאשר בקשה מול רשימת התחנה |
| `listUsersWithClaims` | מנהל-על | רשימת משתמשים והרשאותיהם |
| `whoAmI` | כל מחובר | אבחון — מה השרת רואה עליי |

**החלטה מ-22.8.2026:** רק מנהל-על מעניק תפקידים. אם בהמשך זה יכביד,
ההרחבה לרכזת משאבי אנוש היא שינוי של שורה אחת ב-`setUserRole`.

## המלכודת שחוזרת

אחרי כל שינוי תפקיד, ואחרי אימות מייל, **הטוקן הישן עדיין נושא את
הערכים הקודמים**. גוגל מרעננת אותו לבד רק אחרי כשעה.

לכן, בכל מקום שבו ההרשאות משתנות:

```javascript
await user.getIdToken(true);
```

בלי זה הכל נראה תקין בצד אחד, וכללי האבטחה דוחים בצד השני.

## מה עוד לא נעשה

- `login.html` ו-`admin.html` עדיין מדברים עם המבנה הישן.
  צריך להתאים אותם לקריאה לפונקציות.
- App Check לא מוגדר. מומלץ לפני העלייה לאוויר.
- Delete Protection ו-Point In Time Recovery מכובים במסד הנתונים.
  שווה להפעיל לפני שיש נתונים אמיתיים.
