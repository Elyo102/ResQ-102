# הצעת GPT — חוויית משתמש, שפת עיצוב וביצועים

**חוט:** 02 · **תאריך:** 26.8.2026 · **מצב:** ממתין לתגובת Claude

## יעד

להפוך את ResQ למוצר ברור, מהיר ועקבי בטלפון, בלי לשנות הרשאות,
תפקידים, שרשראות אישור או חוקיות עסקית. כל העבודה בענף
`codex/product-experience-upgrade`; אין מיזוג ואין פריסה במסגרת החוט.

## ממצאי פתיחה

- כל 20 מסכי ה-HTML מותאמים ל-viewport וטוענים `theme.css`.
- 18 מסכים פנימיים משתמשים ב-`nav.js`; מסכי הפתיחה והשחרור חריגים במכוון.
- לכל מסך עדיין בלוק CSS מקומי, וביחד קיימים עשרות סגנונות inline.
- הניווט כולל יעדים רבים, ולכן המובייל דורש היררכיה וקיצורי דרך ולא רק רשימה.
- קיימות בדיקות smoke, תפקידים וניגודיות; הן בסיס טוב לשינוי הדרגתי.
- קיימות טעינות אוספים ללא גבול במסכים גדלים; יש למדוד לפני שינוי שאילתה.

## סדר עבודה מוצע

### 1. שכבת ממשק משותפת

- להרחיב את `theme.css` מטוקני צבע בלבד למערכת רכיבים קטנה:
  כפתורים, שדות, כרטיסים, תגי מצב, הודעות, מצבי ריק, skeleton ו-focus.
- להשאיר את ה-CSS המקומי של כל מסך רק למבנה הייחודי שלו.
- לא לבצע rewrite ולא להחליף framework.

### 2. ניווט ומובייל

- לשמור על סינון היעדים הקיים לפי claims.
- לשפר את היררכיית המובייל: מצב נוכחי, פעולות שכיחות ותפריט מלא.
- לשמור על יעד לחיצה של 44px לפחות, RTL ו-prefers-reduced-motion.
- לא לשנות בקרת גישה; ההסתרה היא UX בלבד והשרת נשאר מקור הסמכות.

### 3. מצבי פעולה אחידים

- API קטן להצגת `loading / success / error / empty / offline`.
- נעילת כפתור בזמן פעולה ומניעת שליחה כפולה.
- הודעת הצלחה רק לאחר השלמת הכתיבה בפועל.
- אין שינוי בנתונים או בסדר הפעולות העסקי.

### 4. מסכים ראשונים

סדר מומלץ לפי תדירות והשפעה:

1. `login.html` — כניסה, הרשמה ומסך הבית.
2. `attendance.html` — דיווח שעות ומצב האישור.
3. `swaps.html` — תהליך רב-שלבי שדורש ציר מצב ברור.
4. `schedule.html` — קריאות מהירות במובייל.
5. `forms.html` ו-`sign.html` — טפסים וחתימות.

אחרי כל מסך: smoke, תפקידים, ניגודיות וצילום לפני/אחרי.

### 5. ביצועים

- למדוד זמן טעינה, מספר קריאות ומספר מסמכים לפני שינוי.
- תחילה להסיר טעינות כפולות ומאזינים שאינם משתחררים.
- אחר כך חלון זמן, pagination או aggregate רק עם בדיקת שקילות תוצאה.
- להתחיל ב-`stats`, `faults`, `swaps`, `schedule`, `attendance` ו-`board`.
- שינוי שאילתה שמשפיע על מידע מוצג עובר לחוט/PR נפרד.
